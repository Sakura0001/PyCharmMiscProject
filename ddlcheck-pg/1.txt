下面是这两段代码合起来后的完整说明文档。整体上，它是一个 **PostgreSQL 并发 DDL/DML 模糊压测工具**，用于在多个数据库、多张随机表上持续并发执行 DDL、DML、事务、会话、对象管理、索引、触发器、规则、函数、过程等 SQL 操作，并记录可复现产物。

---

# 一、总体说明

## 1.1 这两段代码合起来做了什么

这是一套面向 PostgreSQL 的 **并发 DDL/DML Fuzz Stress Runner**。

它的核心目标是：

1. 按数据库名前缀查找目标数据库，例如：

   ```sql
   stress_pg_%
   ```

2. 在这些数据库中查找 `public` schema 下的基础表，主要面向随机表生成器 `pg_random_table_generator.py` 生成的表，例如：

   ```text
   t_rand%
   ```

3. 周期性读取这些表的元数据，包括：

   * 列
   * 列类型
   * 是否可空
   * 是否生成列
   * 索引
   * B-tree 索引
   * CHECK 约束
   * 触发器
   * 继承列
   * 主键列
   * INSERT / UPDATE rule

4. 根据元数据构造合法或尽量合法的 DDL / DML SQL。

5. 按配置的并发度同时执行：

   * DDL 操作
   * DML 操作
   * 事务操作
   * 会话级操作
   * 查询工具类操作

6. 把每次生成和执行的 SQL 都记录下来，方便复现问题。

7. 最后输出压测统计结果和错误汇总。

# 二、程序总流程

## 2.1 启动阶段

程序入口是：

```python
if __name__ == "__main__":
    main()
```

`main()` 做以下事情：

1. 解析命令行参数。
2. 读取配置文件。
3. 命令行参数覆盖配置文件参数。
4. 校验参数合法性。
5. 创建本次运行目录：

   ```text
   output_pg/run_YYYYMMDD_HHMMSS/
   ```
6. 初始化记录器 `Recorder`。
7. 初始化 PostgreSQL CLI 执行器 `PgCli`。
8. 探测当前用户权限。
9. 写出命令覆盖矩阵：

   ```text
   command_coverage_matrix.json
   ```
10. 如果配置了 bootstrap，则自动创建测试库和导入随机表。
11. 开始并发压测循环。

---

## 2.2 压测循环阶段

在 `duration_seconds` 指定的时间内，程序循环执行：

1. 周期性刷新 catalog。
2. 可选清理非基础对象。
3. 重新发现数据库和表。
4. 多线程读取表元数据。
5. 按 DDL / DML 并发度生成操作计划。
6. 为每个操作选择目标表。
7. 根据操作 key 构造 SQL。
8. 把 SQL 写入 `ddl.sql` 或 `dml.sql`。
9. 用线程并发执行所有 SQL。
10. 记录执行结果。
11. 统计成功、失败、错误类型。
12. 到期后写出 `summary.json`。

## 6.7 触发器覆盖

### 6.7.1 CREATE TRIGGER

key：

```text
ddl_create_trigger
```

触发器函数：

```sql
CREATE OR REPLACE FUNCTION public.fn_stress_xxx()
RETURNS trigger
LANGUAGE plpgsql
AS $$
BEGIN
  IF TG_LEVEL = 'STATEMENT' THEN
    RETURN NULL;
  END IF;

  IF TG_OP = 'DELETE' THEN
    RETURN OLD;
  END IF;

  RETURN NEW;
END
$$;
```

执行关键字随机选择：

```sql
EXECUTE FUNCTION
EXECUTE PROCEDURE
```

---

### 6.7.2 覆盖的触发器类型

代码覆盖 7 类触发器变体。

#### 变体 1：BEFORE UPDATE 行级触发器

```sql
CREATE OR REPLACE TRIGGER trg_stress_xxx
BEFORE UPDATE ON table
FOR EACH ROW
WHEN (OLD IS DISTINCT FROM NEW)
EXECUTE FUNCTION public.fn_stress_xxx();
```

覆盖点：

| 项                           | 覆盖 |
| --------------------------- | -- |
| `BEFORE`                    | 是  |
| `UPDATE`                    | 是  |
| `FOR EACH ROW`              | 是  |
| `WHEN` 条件                   | 是  |
| `OLD` / `NEW`               | 是  |
| `CREATE OR REPLACE TRIGGER` | 是  |

---

#### 变体 2：AFTER INSERT OR DELETE 语句级触发器

```sql
CREATE TRIGGER trg_stress_xxx
AFTER INSERT OR DELETE ON table
FOR EACH STATEMENT
EXECUTE FUNCTION public.fn_stress_xxx();
```

覆盖点：

| 项                    | 覆盖 |
| -------------------- | -- |
| `AFTER`              | 是  |
| `INSERT`             | 是  |
| `DELETE`             | 是  |
| `FOR EACH STATEMENT` | 是  |

---

#### 变体 3：AFTER TRUNCATE 触发器

```sql
CREATE TRIGGER trg_stress_xxx
AFTER TRUNCATE ON table
FOR EACH STATEMENT
EXECUTE FUNCTION public.fn_stress_xxx();
```

覆盖点：

| 项                       | 覆盖 |
| ----------------------- | -- |
| `TRUNCATE` event        | 是  |
| statement-level trigger | 是  |

---

#### 变体 4：BEFORE UPDATE OF column

```sql
CREATE TRIGGER trg_stress_xxx
BEFORE UPDATE OF column ON table
FOR EACH ROW
EXECUTE FUNCTION public.fn_stress_xxx();
```

覆盖点：

| 项                  | 覆盖 |
| ------------------ | -- |
| `UPDATE OF column` | 是  |
| 指定列触发              | 是  |

---

#### 变体 5：CONSTRAINT TRIGGER

```sql

AFTER INSERT OR UPDATE ON table
DEFERRABLE INITIALLY DEFERRED
FOR EACH ROW
EXECUTE FUNCTION public.fn_stress_xxx();
```

覆盖点：

| 项                        | 覆盖 |
| ------------------------ | -- |
| `CONSTRAINT TRIGGER`     | 是  |
| `DEFERRABLE`             | 是  |
| `INITIALLY DEFERRED`     | 是  |
| `AFTER INSERT OR UPDATE` | 是  |

---

#### 变体 6：transition table 触发器

```sql
CREATE TRIGGER trg_stress_xxx
AFTER UPDATE ON table
REFERENCING OLD TABLE AS ot_xxx NEW TABLE AS nt_xxx
FOR EACH STATEMENT
EXECUTE FUNCTION public.fn_stress_xxx();
```

覆盖点：

| 项                            | 覆盖 |
| ---------------------------- | -- |
| `REFERENCING OLD TABLE`      | 是  |
| `REFERENCING NEW TABLE`      | 是  |
| transition table             | 是  |
| statement-level AFTER UPDATE | 是  |

---

#### 变体 7：视图上的 INSTEAD OF 触发器

```sql
CREATE OR REPLACE VIEW public.v_stress_xxx AS
SELECT * FROM table LIMIT 10;

CREATE TRIGGER trg_stress_xxx
INSTEAD OF INSERT OR UPDATE OR DELETE ON public.v_stress_xxx
FOR EACH ROW
EXECUTE FUNCTION public.fn_stress_xxx();
```

覆盖点：

| 项                 | 覆盖 |
| ----------------- | -- |
| 视图触发器             | 是  |
| `INSTEAD OF`      | 是  |
| `INSERT`          | 是  |
| `UPDATE`          | 是  |
| `DELETE`          | 是  |
| row-level trigger | 是  |

---

### 6.7.3 DROP TRIGGER

key：

```text
ddl_drop_trigger
```

流程：

1. 创建触发器。
2. 动态查找同名 trigger 所在 relation。
3. 执行动态 SQL 删除 trigger。
4. 删除 trigger function。
5. 删除辅助 view。

核心语句：

```sql
DROP TRIGGER IF EXISTS trigger_name ON schema.table;
DROP FUNCTION IF EXISTS public.fn_stress_xxx() CASCADE;
DROP VIEW IF EXISTS public.v_stress_xxx CASCADE;
```

```sql
DECLARE r record;

    FROM pg_rules

      AND tablename = ...
      AND rulename <> '_RETURN'
```

然后执行：

```sql
MERGE INTO table t

  UPDATE SET column = t.column;
```

保护逻辑：

# 十、CHECK 表达式覆盖

函数：

```python
_build_realistic_check_expr()
```

根据列类型随机选择 CHECK 表达式。

| 类型                      | CHECK 示例                                              |
| ----------------------- | ----------------------------------------------------- |
| 整数                      | `col BETWEEN -1000000000 AND 1000000000`              |
| numeric / float         | `ABS(col) < 1e12`                                     |
| bool                    | `col IN (true, false)`                                |
| text / varchar / bpchar | `char_length(col) BETWEEN 1 AND 256`                  |
| date                    | `col BETWEEN DATE '1970-01-01' AND DATE '2100-12-31'` |

| json / jsonb            | `jsonb_typeof(...) IN (...)`                          |

如果没有合适列，fallback：

```sql
(id IS NULL OR id >= 0)
```

# 十二、并发模型

## 12.1 DDL / DML 并发

每一轮会生成：

```python
ddl_concurrency 个 DDL 操作
dml_concurrency 个 DML 操作
```

例如：

```json
{
  "ddl_concurrency": 4,
  "dml_concurrency": 8
}
```

则每批计划 12 个操作。

---

## 12.2 key rotation 覆盖机制

DDL key 队列：

```python
ddl_q = list(DDL_KEYS)
```

DML key 队列：

```python
dml_q = list(DML_KEYS)
```

每次取队首 key，然后再 append 回队尾。

效果是：

```text
不是纯随机选操作，而是轮转覆盖所有 key。
```

这保证长时间运行时，每种 DDL / DML 类型都会被计划到。

---

## 12.3 执行线程

每个操作一个线程：

```python
threading.Thread(target=run_one_op, ...)
```

同一批次内的 SQL 会并发执行。

# 十九、代码中的几个重要风险点

## 19.1 `ddl_insert_values` 名不副实

DML key：

```text
dml_insert_values
```

实际生成的不是：

```sql
INSERT INTO table VALUES (...)
```

而是和 `dml_insert_select` 一样：

```sql
INSERT INTO table SELECT ... FROM table LIMIT 1
ON CONFLICT DO NOTHING;
```

如果你要精确覆盖 `INSERT VALUES`，这里需要补充独立实现。

---

## 19.2 `caps` 探测了但没有真正用于跳过权限操作

代码探测：

```python
is_superuser
can_createdb
can_createrole
```

但 `ddl_alter_system_set`、`ddl_checkpoint`、`ddl_create_role` 等操作仍然会直接生成并执行。

所以普通用户运行时，这些 SQL 可能大量失败。

---

## 19.3 `VIRTUAL` generated column 可能不兼容部分 PostgreSQL 版本

代码随机生成：

```sql
GENERATED ALWAYS AS (...) VIRTUAL
```

部分 PostgreSQL 版本不支持 `VIRTUAL` generated column，因此可能失败。

---

## 19.4 DDL 和 DML 同时并发可能产生大量预期错误

例如：

* DML 正在 SELECT，DDL DROP COLUMN
* DDL 正在 DROP VIEW，另一个 DDL ALTER VIEW
* DML 正在 UPDATE，DDL 修改列类型
* DDL 创建 rule，DML 执行 MERGE
* DDL DROP TABLE，另一个操作访问该表

这些错误不一定代表数据库 bug，而是并发 fuzz 场景中的预期冲突。

---

## 19.5 `cleanup_non_base_objects()` 会删除很多 public 对象

只要对象不符合 `base_table_prefix%`，就可能被删除：

```sql
DROP TABLE ... CASCADE
DROP VIEW ... CASCADE
DROP MATERIALIZED VIEW ... CASCADE
```

因此不要在生产库或重要测试库运行。

# 二十、最终结论

这两段代码合起来实现的是一个 **PostgreSQL 多数据库、多表、多线程、长时间运行的 DDL/DML 并发模糊压测工具**。

它覆盖的内容非常广，主要包括：

1. **DDL 对象覆盖**

   * table
   * column
   * index
   * check constraint
   * view
   * materialized view
   * trigger
   * function
   * procedure
   * rule
   * schema
   * sequence
   * domain
   * enum type
   * role
   * system setting

2. **DML / 查询覆盖**

   * SELECT
   * SELECT FOR UPDATE
   * SELECT FOR SHARE
   * INSERT SELECT
   * UPDATE
   * UPDATE FROM
   * UPDATE CTE
   * DELETE
   * DELETE USING
   * MERGE
   * RETURNING
   * EXISTS
   * UNION
   * VALUES
   * WITH query

3. **事务与会话覆盖**

   * BEGIN / COMMIT
   * BEGIN / ROLLBACK
   * SAVEPOINT
   * SET TRANSACTION
   * LOCK TABLE
   * PREPARE / EXECUTE
   * CURSOR
   * LISTEN / NOTIFY
   * SET / RESET
   * SHOW
   * DISCARD TEMP

4. **列类型覆盖**

   * integer family
   * float / numeric
   * boolean
   * text / varchar / char
   * date / time / timestamp / timestamptz
   * uuid
   * json / jsonb

5. **触发器覆盖**

   * BEFORE trigger
   * AFTER trigger
   * INSTEAD OF trigger
   * row-level trigger
   * statement-level trigger
   * constraint trigger
   * deferrable trigger
   * transition table trigger
   * INSERT / UPDATE / DELETE / TRUNCATE trigger event

整体看，它不是一个单纯 SQL 生成器，而是一个 **带元数据感知、覆盖轮转、并发执行、失败记录、可复现 artifact 输出的 PostgreSQL 压测框架**。
