# Regress 双执行原始输出稳定性报告

## 判定口径

- 清单：`manifest.jsonl`，SHA-256 为 `60ea761fdcc12238d6adbb53b1aad19ea603e9914dfd27b155ae13c3322756e0`。
- 数据库：PostgreSQL 18.4（`server_version_num = 180004`）。
- 每个 SQL 用例在受控本地环境中执行两次，共 855,913 个用例、1,711,826 次执行。
- 只有两次原始 `stdout` 和原始 `stderr` 均逐字节一致，才判为稳定。SQL 成功或报错不影响稳定性判定。
- 不对 OID、LSN、执行时间、路径、错误行号或其他动态内容作归一化豁免。

## 完整性复核

- 结果文件 1,712 个：前 1,711 个各 500 条，最后一个 413 条。
- 用例序号从 1 到 855,913 连续，无缺失、无重复、无未知序号。
- 855,913 条记录均具备两次运行的原始 stdout/stderr SHA-256。
- 记录中的 `raw_transcript_matches` 与独立哈希重算结果偏差为 0。
- 报告中的稳定/不稳定数量与独立重算结果完全一致。
- 无执行超时、无服务器崩溃或断连；四个工作实例均保持 generation 1。

## 不稳定用例的主要来源

1. 用例自身未实现完全可重复的 setup/cleanup。第一次运行留下对象、依赖、权限或全局状态，导致第二次运行在不同语句处报不同 SQLSTATE，或者出现“对象已存在”。
2. 用例直接输出 PostgreSQL 动态值，例如对象 OID、数据库 OID、WAL LSN 和 `EXPLAIN ANALYZE` 的 Planning/Execution Time。即使语义正确，原始文本也不同。
3. `ALTER SYSTEM`、默认权限、授权、订阅等集群级或持久状态没有在两次运行之间完全恢复，第二次运行观察到的前置状态不同。
4. 2,812 个用例的差异会被旧的归一化比较隐藏；本次严格原始输出判定已将它们全部排除出稳定集合。
