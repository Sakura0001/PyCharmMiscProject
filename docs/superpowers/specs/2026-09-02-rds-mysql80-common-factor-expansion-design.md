# 内部 MySQL 8.0 在线修改列类型公共因子展开设计

## 1. 目标

重新构造在线修改列类型测试工作簿，使“基础功能点”“公共因子”“专项因子”“执行场景”和“验收 Oracle”彼此分离，并生成可审计的执行矩阵。

覆盖范围：

- 内部 MySQL 8.0 实现，不把产品版本或内核小版本作为测试维度。
- 整数类型在线/秒级扩宽。
- `CHAR`、`VARCHAR` 长度扩展。
- `DECIMAL(M,D)` 在 `M` 增大且 `D` 不变时的 `INPLACE` 增强。
- 带索引虚拟生成列及函数索引相关的 `INT -> BIGINT`、`INPLACE + LOCK=SHARED` 增强。
- DDL 唯一键临时冲突优化。
- 表、数据、并发、资源、故障、复制及恢复等公共背景。

## 2. 核心术语

### 2.1 基础功能点

基础功能点描述一个不可再拆分的被测行为和一个主要结果，例如：

- `SIGNED TINYINT -> SMALLINT` 请求 `ALGORITHM=INSTANT`。
- `VARCHAR(255) -> VARCHAR(256)` 请求 `ALGORITHM=INPLACE`。
- `DECIMAL(10,2) -> DECIMAL(18,2)`。
- 已有普通二级唯一索引的 Online DDL 在 Row Log 回放时遇到临时重复键。

基础功能点不包含表规模、行格式、表空间、目标列位置或并发线程数等公共背景。

### 2.2 公共因子

公共因子描述可复用于多个功能域的环境、表结构背景、物理存储、数据状态或运行负载。每个基础功能点必须对每个公共因子给出以下适用状态之一：

- `ALL_LEVELS`：该因子的所有合法取值必须覆盖。
- `PINNED`：基础功能点已经固定该因子，只执行固定值。
- `CONSTRAINED`：只允许部分值，或因子值会改变预期。
- `N/A`：不适用，必须记录原因和约束编号。

### 2.3 专项因子

专项因子只服务于一个功能族，例如：

- 整数源/目标类型、符号属性。
- `VARCHAR` 长度前缀字节边界。
- `DECIMAL` 的 `M/D` 关系及 9 位存储分组边界。
- 目标列是否进入索引、分区键、外键或生成列表达式。
- 唯一键冲突类型、事务提交顺序和 Row Log 阶段。
- `ALGORITHM`、`LOCK` 和功能开关。

### 2.4 Oracle

Oracle 是复用的检查包，不作为功能点或公共因子。检查包至少包含：算法路径、锁和 MDL、Schema、数据、索引、分区、并发提交、错误码、原子性、资源、复制与恢复。

## 3. 覆盖策略

采用用户确认的方案 A：

1. 每个基础功能点先生成一条完整公共基线用例。
2. 对每个适用公共因子的每个非默认值，生成一条 OFAT 用例；本行只替换一个公共因子值，其余公共因子保持基线。
3. 每条执行用例都展开完整公共因子列，不只记录场景名。
4. P0 功能点增加约束化 Pairwise，使任意两个适用公共因子的每个合法值对至少共同出现一次。
5. P0 高风险路径增加定向三因子或局部穷举组合。
6. 无效组合不能静默删除，必须进入约束表并记录原因。
7. 公共因子改变功能资格时，重新派生算法、锁和成功/失败预期，不能复制基础功能点预期。

### 4.7 默认公共基线

`BASE-GLOBAL` 固定为：内部 MySQL 8.0、InnoDB 持久非分区表、`ROW_FORMAT=DYNAMIC`、file-per-table、12 列普通变长行、单列主键、目标列位于中间且无索引或依赖、`NULL DEFAULT NULL`、1 个不包含目标列的普通二级索引、100,000 行边界值与均匀数据、10% NULL、新装载且已更新统计信息、热缓存、充足磁盘和临时空间。并发基线为 `1 DDL + 2 读 + 2 写`、每线程 10 QPS、RR、autocommit，持续时间上限 60 秒或每线程 10,000 次操作。

OFAT 行只替换一个公共因子值，其他列显式继承 `BASE-GLOBAL`。如果替换值与基线冲突，约束规则负责同步修改依赖列，例如 `DS-EMPTY` 同时把 NULL 比例和数据分布标记为不适用，但这仍只算一个数据规模变化场景。

## 5. 单表累计 INSTANT 次数

累计 INSTANT 历史既是公共表历史因子，也是独立的极限场景。执行环境在运行前解析内部实现的 `INSTANT_LIMIT`，所有用例使用相对值，避免绑定产品版本。

| 场景 | 执行前累计次数 | 本次操作 | 重点结果 |
|---|---:|---|---|
| 新表首次 | 0 | 第 1 次显式 INSTANT | 成功并正确增加计数 |
| 低次数 | 1、2、8、16、32 | 再执行一次 | 每次路径和计数一致 |
| 上限前 | `INSTANT_LIMIT-1` | 显式 INSTANT | 成功并达到上限 |
| 已达上限 | `INSTANT_LIMIT` | 显式 INSTANT | 明确拒绝且不修改 Schema/数据 |
| 超过上限默认算法 | `INSTANT_LIMIT` | 省略算法或 DEFAULT | 按内部规则回退或拒绝，不能误报 INSTANT |
| 连续失败 | `INSTANT_LIMIT` | 重复显式 INSTANT | 计数不继续增长，无元数据泄漏 |
| 重建复位 | `INSTANT_LIMIT` | COPY/重建后再 INSTANT | 计数复位后首次操作成功 |
| 单列连续扩长 | 逐次增加 VARCHAR 长度 | 直到上限 | 同一目标列累计行为正确 |
| 多列轮换 | 多个列轮换执行 INSTANT | 直到上限 | 上限按表而不是按列生效 |
| 混合历史 | INSTANT 加/删列与类型修改混合 | 直到上限 | 所有计入操作的计数口径一致 |
| 分区表历史 | 一级及 64 种二级分区表 | 上限前/上限/重建后 | 各分区元数据和表级计数一致 |
| 故障边界 | 上限前一次操作在提交边界重启 | 恢复后读取计数 | Schema 与计数原子一致 |

观察项包括内部计数元数据、算法阶段、表重建证据、DDL 错误码、Schema 原子性、旧行和新行读取、并发 DML 提交集合、恢复后的计数与定义一致性。

## 6. 二级分区定向覆盖

公共因子表为 64 个二级分区有序组合逐一建立值 ID。对所有支持分区表的基础功能点，OFAT 至少生成 64 条二级分区变体。

P0 额外覆盖：

- 64 种组合 × 目标列为非分区键的成功路径。
- 64 种组合 × 目标列直接属于一级分区键的限制路径。
- 64 种组合 × 目标列直接属于二级分区键的限制路径。
- 64 种组合 × 一级与二级分区表达式间接引用目标列的限制路径。
- 64 种组合 × 空分区、热点分区、跨分区并发写。
- 代表性 P0 功能点中，64 种组合与 `DS-10M`、`DS-100M` 做定向交叉。
- 唯一索引场景校验一级、二级分区键包含规则及最终唯一性。
- DDL 成功和失败后逐分区核对分区边界、行数、校验和、索引可用性和裁剪计划。

## 7. 每个执行场景的重点观察

每条执行用例必须包含下列字段，禁止只写“DDL 成功”或“数据一致”：

- `主要风险`：该组合最可能暴露的问题。
- `重点观察`：本场景最重要的 1～3 个现象。
- `观察方法`：使用的元数据、PFS 阶段、MDL、错误码、行数、校验和、分区统计、延迟或资源指标。
- `通过标准`：可直接判定通过/失败的结果。
- `派生预期算法`：INSTANT、INPLACE、COPY、拒绝或按内部规则。
- `派生预期锁`：DEFAULT、NONE、SHARED、EXCLUSIVE、MDL 等待或不适用。
- `读并发预期`、`写并发预期`：允许、短暂停顿、等待、阻塞或失败。
- `数据预期`：旧值、并发提交、回滚事务、索引和分区归属。
- `资源预期`：扫描量、临时空间、Online Alter Log、CPU、I/O 和复制延迟。
- `原子性预期`：失败或故障后仅允许全旧或全新状态。

重点观察由功能点、变化的公共因子和约束规则共同生成。例如：

- `ROW_FORMAT=COMPRESSED`：重点观察算法是否退化、压缩表空间兼容、临时空间和 I/O 放大。
- `DS-100M`：重点观察耗时是否符合算法性质、扫描量、DML 延迟、Row Log、磁盘峰值和复制延迟。
- `LOCK=SHARED`：重点观察 SELECT 持续成功、所有写入等待、最终 MDL 切换以及释放后写入恢复。
- 二级分区：重点观察一级/二级分区边界、逐分区行数、分区裁剪、局部/全局索引和跨分区 DML。
- INSTANT 上限：重点观察累计计数、显式算法严格性、默认算法回退和重建复位。

## 8. 组合约束

至少实施以下约束：

1. 非 InnoDB 不沿用 InnoDB 在线 DDL 预期。
2. 无效的行格式与表空间组合在建表阶段记录为不适用，不静默删除。
3. 空表不能声称覆盖 NULL 比例、重复密集、热点或 Row Log 回放。
4. 单行表不能声称覆盖重复键、热点或并发冲突分布。
5. 目标列为索引列或一级/二级分区键时，按对应功能资格重新派生预期。
6. 二级分区的唯一键必须满足内部一级和二级分区键包含规则。
7. 字符集和排序规则只作用于字符列及字符串唯一键。
8. DECIMAL 数据模板只作用于 DECIMAL 功能域。
9. Row Log 注入只作用于持续时间足够且允许并发写的重建路径。
10. `LOCK=SHARED` 的写操作预期是等待，不能以没有 Row Log 判为失败。
11. 预检查失败的负向点不重复执行无意义的亿级数据场景。
12. 累计 INSTANT 次数已被基础点固定时，不再与自身次数因子重复交叉。
13. 故障、空间不足、重启、切主和亿级数据仅在授权的一次性环境执行。
14. 相同功能点、因子值和专项条件不得产生重复执行用例 ID。

## 10. 展开行结构

每条 OFAT 或组合增强行至少包含：

- 执行用例 ID、基础功能点 ID、功能域、优先级、执行层级。
- 基础功能行为、专项因子和 DDL 动作描述。
- 公共基线 ID、变化因子 ID、变化值 ID、适用状态、约束 ID。
- 分区层级、一级分区类型、二级分区类型、分区/子分区数量。
- 行格式、表空间、表宽、目标列位置、目标列属性、主键组织。
- 数据规模、数据画像、NULL 比例、碎片和缓存状态。
- 并发 DML、线程数、速率、事务、隔离级别、MDL 和注入阶段。
- INSTANT 历史次数和上限状态。
- 派生算法、派生锁、成功/失败、读写并发、原子性和资源预期。
- 主要风险、重点观察、观察方法、通过标准和 Oracle 包 ID。
- 执行状态、实际结果、缺陷编号。

## 11. 覆盖验收

工作簿只有同时满足以下条件才算完整：

1. 每个保留基础功能点至少有一条公共基线用例。
2. 对每个基础功能点、每个适用公共因子和每个合法取值，至少有一条 OFAT 用例。
3. 64 个二级分区有序组合全部存在，且每个支持分区表的功能点都能追溯到对应覆盖行或明确的不适用原因。
4. 扫描、重建和 Row Log 路径包含千万、亿级、上亿及超过 Buffer Pool 的场景。
5. 每个适用 INSTANT 功能点覆盖新表、上限前、达到上限、超过上限和重建复位。
6. 每条执行场景均有非空的重点观察、观察方法和通过标准。
7. P0 的 Pairwise 和定向高风险组合无覆盖缺口。
8. 所有非法组合均可追溯到约束 ID。
9. 原 815 条记录全部有审计去向，不因重构而无说明丢失。
10. 工作簿公式无错误，测试点 ID 和执行用例 ID 全局唯一。
